# 🎨 화면 설계서 (UI)

기준: `main`(3d63e58). 화면 = Thymeleaf 템플릿(`src/main/resources/templates/`).

## 1. 프론트엔드 구조

| 항목 | 내용 |
|---|---|
| 렌더링 | 서버 사이드 (Thymeleaf). 부분 갱신은 `fetch` + DOM 조작 |
| 공통 레이아웃 | `fragments/layout.html` — `head(pageTitle)`, `header`(전역 네비), `companion`(챗봇 위젯) 프래그먼트 |
| 스타일 | 단일 `static/css/app.css` |
| 스크립트 | 화면별 vanilla JS (`static/js/*.js` 20개). 번들러 없음 |
| 실시간 | `vendor/sockjs.min.js` + `vendor/stomp.min.js` (채팅·DM) |
| CSRF | `csrf.js`가 메타 태그의 토큰을 모든 비-GET `fetch`에 자동 첨부 |
| 다국어 | 헤더의 `ko` / `ja` 링크로 `?lang=` 전환. `messages_ko/ja.properties` |

### 전역 네비게이션 (`header` 프래그먼트)

`홈(/)` · `파티(/party-board)` · `추천글(/recommendations)` · `메시지(/messages)` · `내 파티(/my-parties)` · `마이페이지(/mypage)` · (관리자만) `관리자(/admin)` · 로그인/로그아웃 · 언어 토글 · 알림 벨(`notifications.js`)

## 3. 화면 상세

### S-01 홈 / 탐색 (`index.html`)

- **구성**: 히어로 + 관리자 배너, 지역/스타일 태그로 파티·패키지 탐색, 인기 게시글, 챗봇 위젯 진입.
- **동작**: `main-explore.js`가 필터 변경 시 목록 갱신. 비로그인도 열람 가능, 신청·글쓰기 시 로그인 유도.

### S-02 로그인 (`auth/login.html`)

- **입력**: 이메일, 비밀번호. (Spring Security 폼, action `/login`, 파라미터 `email` / `password`)
- **부가**: 구글·네이버 소셜 버튼(`/oauth2/authorization/{google|naver}`), 회원가입 링크.
- **에러**: `?error=` 쿼리로 실패 메시지 표시(잘못된 계정, 5회 실패 잠금 등).

### S-03 회원가입 (`auth/signup.html`) — `signup.js`

- **단계**: ① 이메일 입력 → 중복확인(`GET /api/auth/email-check`) ② 비밀번호 ③ 이름·성별·생년월일·국적 ④ 휴대폰 입력 → 인증번호 발송(`POST /api/verification/phone/send`) → 확인(`/confirm`) ⑤ 제출(`POST /api/auth/signup`).
- **검증**: 만 14세 이상, 이메일/휴대폰 형식·중복, 인증 완료 여부.

### S-10~S-11 파티 목록/상세 (`party/board.html`, `party/detail.html`) — `party-apply.js`

- **목록**: 카드형(썸네일, 제목, 지역, 출발일, 정원 n/N, 스타일 태그, 조건 뱃지). 지역·태그 필터.
- **상세**: 파티 정보 + 조건(성별/연령/국적) + 방장 정보 + 참가 신청 폼(메시지). 이미 신청 시 "신청 취소". 정원 초과/조건 불일치 시 사유 노출.

### S-13 파티 전용 룸 (`party/room.html`) — `party-room.js`

- 파티원만(`NOT_PARTY_MEMBER` 아니면 접근). 파티 채팅(STOMP), 신청자 승인/거절 목록(방장), 계획표 바로가기, 강퇴/탈퇴.

### S-15 협업 플래너 (`planner/index.html`) — `planner.js` + `planner-owner.js`

핵심 화면. 주요 DOM:

| 영역 | id | 설명 |
|---|---|---|
| 시간 그리드 | `grid-head` / `grid-body` | N일차 × 시간(분) 격자. 일정 블록 드래그 배치·리사이즈 |
| 범례 | `legend` | 스타일 태그별 색상 |
| 빠른 추가 | `quick` / `btn-add` / `btn-clear` | 커스텀 일정 추가 / 전체 비우기 |
| 편집권 배너 | `lock-banner` / `lock-holder-name` / `lock-holder-me-badge` | 현재 편집권 보유자 표시 |
| 방장 메뉴 | `owner-menu` (`toggle`/`body`/`arrow`) | 접이식 |
| 편집권 부여/회수 | `lock-target-select` / `btn-grant-lock` / `btn-revoke-lock` | 파티원 선택 후 부여, 방장이 회수 |
| 저장 | `btn-manual-save` | 수동 저장. 방장 화면 열려 있으면 주기 자동저장(`AUTO_SAVE_INTERVAL_MS`) |
| 스냅샷 | `snapshot-list` | 저장 시점 타임라인 + "이 시점으로" 롤백 버튼 |
| AI | `ai-text` / `ai-send` | 활동 추천 요청 |
| 요약/합계 | `summary` / `total-price` | 일정 요약, 예상 비용 |
| 제출 | `btn-submit` | 계획표 제출(이후 자유편집 잠금) |
| 투표 | `chat` 영역 등 | 찬반 투표 UI |
| 토스트 | `toast` | 저장/에러 알림 |

- **읽기전용 규칙**: `IS_LOCK_HOLDER=false`면 추가/삭제 버튼 비활성. 편집권 없는 사람이 API 호출 시 `LOCK_NOT_HELD`.
- `btn-pay`는 결제 잔재 — v16 제거 대상.

### S-19 마이페이지 (`mypage/index.html`)

- **섹션 순서**: 프로필 카드 → 지역 정복 지도(히트맵) → 칭호 관리 → 여행 거리/통계 → 참여 파티·완료 여행.
- **프로필 카드**: 아바타(업로드 `avatar-upload.js`), 이름, 매너온도(읽기전용), 자기소개 인라인 수정(`POST /api/mypage/intro`), 배경 테마.
- **히트맵**(`mypage-heatmap.js`): 완료 파티/스냅 기준 방문 지역 집계 → 한국/일본 지도 색칠.
- **칭호**(`mypage-titles.js`): 8카테고리 × 총 38종. 획득/미획득 구분, 장착 선택.
- ⚠️ 현재 `TitleService` NPE로 500 발생 (TNSM-97) — `category`가 NULL인 칭호 행이 있을 때.

### S-27~S-30 관리자

- 좌측 탭: 회원 / 파티 / 배너 / 신고.
- **회원**: 목록 + 정지·복구, 관리자 권한 부여·회수.
- **파티**: 목록 + 강제 종료.
- **배너**: 등록(개수 제한)·삭제, 홈 노출.
- **신고**: 대기/처리/기각 필터, 처리 시 조치(none/hidden/deleted) 선택 → `action_taken`·`actioned_by` 기록.

### G-01 동행 챗봇 위젯 (`fragments/layout.html#companion`) — `companion-widget.js`

- 모든 페이지 우하단 플로팅. 비로그인도 사용(`/api/companion/chat` permitAll).
- 대화형으로 지역·동행 유형·스타일 물어보고 파티/활동 추천. AI 크레딧 차감(로그인 시).

## 4. 화면 흐름 (주요 시나리오)

```
회원가입 → 로그인 → 홈
  홈 → 파티 목록 → 파티 상세 → 신청
       (방장) 파티 개설 → 신청 승인 → 파티 룸
  파티 룸 → 협업 플래너 → 일정 편집(편집권) → 저장/스냅샷 → 제출 → 찬반 투표
  여행 후 → 게시판 글 작성 → 마이페이지(히트맵·칭호 갱신)
  문제 발생 → 신고 → (관리자) 신고 처리
```

## 5. 공통 UI 규칙

| 항목 | 규칙 |
|---|---|
| 반응형 | 모바일 우선. 카드/그리드는 `flex`/`grid` + `gap` |
| 상태 표시 | 파티 `recruiting/full/closed/completed`, 계획표 `draft/submitted/confirmed`, 신고 `pending/resolved/dismissed` 를 뱃지 색으로 구분 |
| 빈 상태 | 목록 비었을 때 안내 문구(예: "아직 저장된 시점이 없어요.") |
| 확인 다이얼로그 | 되돌리기·강퇴·삭제 등 비가역 동작은 `confirm()` |
| 알림 방식 | 성공/실패는 토스트 또는 `alert`, 폼 검증은 인라인 |
| 접근성 | 시맨틱 태그, 버튼 `disabled` 시 사유 `title` 노출 |
