# 📑 프로젝트 기획서

## 1. 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 타노시미 투어 (tanoshimi) |
| 한 줄 정의 | 한일교류 여행 파티 매칭 + 실시간 협업 일정 계획 + AI 여행 추천 서비스 |
| 형태 | 웹 애플리케이션 (반응형, 서버 렌더링) |
| 저장소 | `genuinekumquat/tanoshimi` |
| 기준 제안서 | v16 |

"타노시미(楽しみ)" = 기대·즐거움. 여행을 **함께 갈 사람 찾기**부터 **일정 짜기**, **다녀와서 기록**까지를 한 서비스에서 잇는 것이 목표.

## 2. 배경 & 문제 정의

- 개인 여행자가 한일 여행에서 **동행을 구하기 어렵다** — 조건(성별·연령·국적·여행 스타일)이 맞는 사람을 찾을 채널이 없음.
- 여러 명이 여행 일정을 짤 때 **카톡 + 엑셀 + 지도**를 오가며 소통 비용이 큼. 누가 뭘 바꿨는지, 최신본이 뭔지 관리가 안 됨.
- 여행지 활동을 고를 때 **날씨·실내외·이동 동선**을 사람이 일일이 따져야 함.

## 3. 목표

| 구분 | 목표 |
|---|---|
| 사용자 가치 | 조건 기반 동행 매칭, 실시간 공동 일정 편집, AI가 보조하는 활동 추천·동선·현실성 검토 |
| 기술 목표 | Spring Boot 단일 모놀리식 위에서 실시간(WebSocket), 외부 AI/지도/날씨 연동, 역할별 병행 개발이 가능한 모듈 경계 |
| 산출물 | 동작하는 서비스 + 개발 문서(본 docs) + 발표/시연 |

## 4. 대상 사용자

| 페르소나 | 설명 | 주요 기능 |
|---|---|---|
| 여행 동행을 구하는 개인 | 20~30대 한/일 여행자 | 파티 탐색·신청, 파티 채팅, 공동 일정 |
| 파티장(호스트) | 모임을 만들고 운영 | 파티 개설·신청 승인·강퇴, 일정 편집권 관리 |
| 여행 기록/커뮤니티 이용자 | 후기·사진 공유 | 게시판, 추천글, 팔로우, 칭호 수집 |
| 관리자 | 운영자 | 회원·파티·신고·배너 관리 |

## 6. 기술 스택

| 계층 | 사용 기술 |
|---|---|
| 언어/런타임 | Java 21 |
| 프레임워크 | Spring Boot 3.5.15 (Web MVC, Data JPA, Security, OAuth2 Client, WebSocket, WebFlux WebClient) |
| 빌드 | Gradle (Groovy DSL) |
| 뷰 | Thymeleaf + `thymeleaf-extras-springsecurity6`, 서버 사이드 렌더링 |
| 프론트 | Vanilla JS (`static/js/*.js` 20개), 단일 `app.css`, SockJS + STOMP (`vendor/`) — 별도 노드 빌드 없음 |
| DB | MySQL 8 (`utf8mb4`), Hibernate `ddl-auto: update` + 수동 `schema.sql`/마이그레이션 |
| 실시간 | STOMP over WebSocket — 엔드포인트 `/ws`, 브로커 `/topic`, 앱 prefix `/app` |
| 파일/이미지 | Apache Tika(타입 검증), metadata-extractor(EXIF GPS 추출), webp-imageio(변환), AWS S3 / Rekognition SDK(의존성 포함) |
| 외부 연동 | SMS(알리고), 날씨(KMA/OpenWeather), 번역(Papago/DeepL), AI(Anthropic/Gemini) — 전부 `mock` 기본, 키는 `application-local.yml` |
| 인증 | Spring Security Form Login (username 파라미터 = `email`), OAuth2 (Google, Naver), BCrypt |
| 테스트 | JUnit 5, `spring-security-test`, H2 (test runtime) |

### 배포/실행 프로파일

- 기본 프로파일 `local`. 비밀값(`DB`, `OAuth secret`, 외부 API 키)은 `application-local.yml`(git 미추적) 또는 환경변수로만 주입.
- 업로드 파일 저장 위치: `${user.home}/tanoshimi-uploads` (프로젝트 폴더 밖 — 재배포 시 유실 방지).

## 10. 리스크 & 대응

| 리스크 | 대응 |
|---|---|
| 외부 API(날씨·번역·AI) 키·비용 | 전부 `mock` 프로바이더 기본 제공, 키 없이도 개발/시연 가능하게 설계 |
| 역할별 병행 개발 시 스키마 충돌 | `schema.sql` 단일 원본 + 번호 붙은 마이그레이션 파일, 머지 전 컴파일 확인 |
| 실시간 동시편집 충돌 | 자유 편집이 아닌 **편집권(lock) 단일 보유** 방식 + 주기 자동저장 + 스냅샷 롤백 |
| 결제 기능 제거 잔재 | 엔티티·`schema.sql`에서 예약/결제 3테이블 정리 필요(별도 작업) |
| 테스트 커버리지 낮음 | 통합 QA 단계에서 핵심 시나리오 위주 보강 |
