## 1. 요약

- 로컬에서 **Gemini API 호출이 전부 실패**하고 있다. 처음엔 키가 401(인증 실패), 새 AI Studio 키로
  바꾼 뒤엔 **402 "prepayment credits are depleted"**(선불 크레딧 소진). 키 문제가 아니라 **결제** 문제다.
- 그래서 AI 기능은 각자의 **폴백**으로 동작 중이다. 시연 중 화면이 깨지지는 않지만,
  "AI가 입력을 보고 추천/분석한다"는 모습은 지금은 보여줄 수 없다.
- Google One(Google AI Pro 등) 구독은 소비자용 Gemini 앱 요금이고, **Gemini API 결제와는 별개**다
  (구독 혜택으로 API 크레딧이 붙는지는 계정별로 AI Studio 결제 화면에서 확인 필요).
- 번역·날씨·SMS·메일은 로컬 설정상 원래 mock/log 로 돌고 있어 **실제 외부 API는 테스트되지 않았다.**

## 2. 외부 연동 현황 (로컬 `application-local.yml` 기준)

| 기능 | provider | 상태 |
|---|---|---|
| Gemini — 계획표 AI 추천·AI 검증·AI 리포트 (`RealGeminiClient`) | `gemini` | ❌ 402 크레딧 소진 → 폴백 |
| Gemini — 마스코트 자유 대화 "💬 대화하기" (`GeminiChatClient`) | `gemini` | ❌ 같은 키·같은 결제 → 실패 |
| 번역 (채팅·게시글·파티 제목 번역 버튼) | `mock` | ⚠️ 가짜 번역. 파파고/DeepL 미검증 |
| 날씨 (추천 시 실내/실외 판단) | `mock` | ⚠️ 가짜 날씨. 기상청/OpenWeather 미검증 |
| SMS 인증 | `log` | ⚠️ 콘솔 출력만 |
| 메일 (인증·임시 비밀번호) | `log` (SMTP host 비어 있음) | ⚠️ 콘솔 출력만 |
| 소셜 로그인 Google / Naver | 값 있음 | ❓ 이번 점검에서 미검증 |
| 소셜 로그인 LINE | 더미값 | ❌ 동작 안 함 |

공용 `application.yml` 은 팀 전체 기본값이라 `app.companion.provider: mock` 을 유지한다.
실제 키는 각자 `application-local.yml`(gitignore 됨) 또는 환경변수 `GEMINI_API_KEY` 로 넣는다.

## 3. Gemini 를 쓰는 곳과 실패 시 동작

| 위치 | 하는 일 | Gemini 실패 시 |
|---|---|---|
| `ChatbotActivityService.recommend()` ← 계획표 타미 추천 | DB 관광지 + 사용자 입력을 보내 5개 추천 | DB(`activities`, 6개 지역 23건)에서 **그 지역 앞 5개를 그대로** 반환 — **입력 문장은 무시됨** |
| `ChatbotActivityService.extractCoreTagWithGemini()` | 입력에서 핵심 태그 추출 | 폴백 |
| `PlannerController.aiValidate()` ← "일정 AI 검증 브리핑" | 이동시간·현실성 검토 후 새 일정 제안 | 안내 JSON(briefing) 으로 대체 |
| `PlannerController.report()` ← "플랜 PDF로 인쇄하기" | 일정 HTML 리포트 생성 | "지금은 AI가 잠깐 쉬고 있어요…" 안내 문구 |
| `GeminiChatClient` ← 모든 화면의 "💬 대화하기" | 자유 대화 | 에러 안내 |

즉 지금 계획표에서 타미가 보여주는 추천 카드는 **AI 결과가 아니라 DB 시드 데이터**다.
"후쿠오카 라멘 추천해줘"라고 해도 항상 같은 후쿠오카 5곳이 같은 순서로 나온다.

## 4. 키 넣는 법 / 확인하는 법

1. https://aistudio.google.com/apikey 에서 키 발급 (형식이 `AIza…` 가 아닐 수 있음 — AI Studio 에서 만든 키면 그대로 사용)
2. `src/main/resources/application-local.yml`
   ```yaml
   app:
     companion:
       provider: gemini
       api-key: <발급받은 키>     # 채팅/문서에 붙여넣지 말 것
       model: gemini-3.5-flash-lite
   ```
3. 서버 재시작 후 계획표 → "플랜 PDF로 인쇄하기" 가 안내 문구가 아닌 실제 리포트로 나오면 성공.
   서버 로그의 `Gemini Real API call failed` 뒤 HTTP 코드로 원인 구분:
   **401** 키 오류 / **402** 결제·크레딧 / **404** 모델 이름 / **429** 호출 한도.

## 5. 선택지 (회의에서 결정)

**A. Gemini 결제**
- A-1. 키 프로젝트에 크레딧 충전 (https://ai.studio/projects → 해당 프로젝트 결제). 시연용이면 소액.
- A-2. 결제 가능한/무료 등급이 적용되는 다른 프로젝트에서 키 발급 — 적용 여부는 발급 후 호출해 봐야 앎.

**B. 결제 없이 가기**
- B-1. **추천 폴백 개선 (제안)**: Gemini 실패 시 입력 문장의 단어(라멘·신사·야경…)를 DB 관광지 이름/설명과
  매칭해 관련 있는 것부터 보여준다. 비용 0, 시연에서 입력에 반응하는 것처럼 보임.
  한계: DB 관광지가 23건뿐이라 다양성이 낮다(필요하면 시드 추가).
- B-2. `provider: mock` 전환 — mock 에 추천용 응답 처리가 있으나 리포트/브리핑이 시연에 쓸 만한지 **미확인**.

추천: **B-1 을 먼저 해 두고, 여유가 되면 A-1** — 크레딧이 있으면 진짜 AI, 없으면 키워드 맞춤 DB 추천.

## 6. 타미(마스코트)의 메인 화면 역할

현재: 모든 화면 우하단에 Live2D 캐릭터 + "💬 대화하기"(자유 대화 챗봇, Gemini).
문제: 메인에서 무엇을 하는 캐릭터인지 불분명하고, 이번 점검에서 신청 버튼·채팅·추천 카드를
여러 번 가렸다(투명 영역 클릭 통과는 #60, 모바일 숨김은 #66 에서 처리). 자유 대화도 Gemini 라 지금은 응답 불가.

| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 파티 찾기 도우미 (제안)** | 메인에서 말풍선 "어디로 떠나볼까 멍? 🐾" + 버튼 "이번 주 출발 파티 / 먹방 파티 / 오사카 파티 / 처음이에요(이용 방법)" → 필터된 파티 게시판 또는 이용 안내(파티 찾기 → 신청 → 채팅 → 계획표) | AI 없이 동작 → 시연 실패 위험 없음. 핵심 기능(파티 매칭)으로 연결 |
| B. 메인에선 숨기기 | 캐릭터는 계획표(AI 여행 도우미)에서만 | 가장 간단, 가림 문제 해소. 캐릭터 존재감↓ |
| C. 현행 유지 | 자유 대화 챗봇 | Gemini 결제가 풀려야 의미. 시연 중 응답 지연/엉뚱한 답 위험 |
