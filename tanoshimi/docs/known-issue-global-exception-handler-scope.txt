알려진 이슈 — GlobalExceptionHandler 스코프 누락
발견일: 2026-09-01
발견 경위: TNSM-96(유저 차단) 기능 테스트 중, 파티 신청 차단(BLOCKED_USER) 응답을
           브라우저에서 확인하다가 우연히 발견함. 특정 담당자의 실수가 아니라
           구조적으로 처음부터 스코프가 좁게 잡혀 있던 문제로 보임.
상태: 미수정, 보류 (허수연 팀장 판단 - 당장은 두고, 필요시 별도 처리)

===============================================================
증상
===============================================================
BusinessException을 던지는 API가 깔끔한 JSON 에러
({"success":false,"message":"..."}) 대신 스프링 기본 에러 페이지
(500 + Java 스택트레이스 그대로)를 그대로 클라이언트에 반환한다.

실제로 발생한 예:
  POST /api/parties/{id}/apply 에서 CANNOT_APPLY_BLOCKED_PARTY 예외가
  파티 컨트롤러 밖으로 스택트레이스와 함께 그대로 노출됨.

===============================================================
원인
===============================================================
src/main/java/net/datasa/tanoshimi/exception/GlobalExceptionHandler.java

  @RestControllerAdvice(annotations = RestController.class)

이 어노테이션이 "@RestController 로 선언된 클래스"에만 적용되도록
스코프를 제한하고 있다. 그런데 아래 컨트롤러들은 화면 렌더링용
@Controller 로 선언돼 있으면서, 그 안의 일부 메서드에만
@ResponseBody 를 달아 API 처럼 쓰고 있다. 이 메서드들에서 던진
예외는 GlobalExceptionHandler 를 타지 않고 스프링 기본 에러
핸들링(Whitelabel)으로 빠진다.

영향받는 컨트롤러 (@Controller + @ResponseBody 혼용, 6개):
  - MyPageController
  - PostController
  - PartyController      <- 이번에 직접 재현됨
  - PlannerController
  - RecommendationController
  - PartyRoomController

===============================================================
왜 신경 써야 하는지
===============================================================
단순 UX 문제가 아니라, 사용자에게 내부 패키지/클래스 구조가 담긴
Java 스택트레이스가 그대로 노출되는 정보 노출(information disclosure)
이슈다. 로컬 개발 중에는 괜찮지만, 이 상태로 배포되면 파티 정원 초과·
성별 제한 등 흔한 에러 상황에서도 사용자가 스택트레이스 화면을 보게 될
수 있다.

===============================================================
가능한 해결 방향 (아직 결정/적용 안 함)
===============================================================
1. GlobalExceptionHandler 의 @RestControllerAdvice 스코프를 넓힌다
   - 단, 단순히 annotations 제약을 없애면 화면 렌더링(HTML) 메서드의
     예외까지 전부 JSON 으로 응답하게 되어 정상 에러 페이지가 깨진다.
     메서드 단위(@ResponseBody 여부)로 분기하는 별도 처리가 필요함.
2. 위 6개 컨트롤러의 @ResponseBody API 메서드들을 별도의
   @RestController 클래스로 분리한다 (더 큰 리팩터링, 여러 담당자
   영역에 걸침).
3. 각 컨트롤러에 로컬 @ExceptionHandler 를 개별로 추가한다
   (임시방편, 중복 코드 발생).

===============================================================
결정
===============================================================
2026-09-01 기준: 여러 담당자 컨트롤러에 걸친 공통 인프라 문제라
오채원 담당 범위(TNSM-96)에서 임의로 고치지 않고 보류하기로 함.
필요 시 팀장이 별도 작업으로 판단.
