## 2. 시연 PC 준비

### 2-1. DB

새 DB 라면 [`db/README.md`](../src/main/resources/db/README.md) 의 "처음 로컬 DB 세팅하는 순서" 를 그대로 따른다. 그다음 데모 데이터를 넣는다 (`tanoshimi/tanoshimi` 기준):

```bash
# 마이페이지 데모(유자차) - 1차 실행 → 서버 켜고 유자차로 /mypage 한 번 열기 → 2차 실행 (파일 상단 주석 참고)
mysql -u scit -p --default-character-set=utf8mb4 < src/main/resources/db/demo_mypage_seed.sql

# 메인 "모집 마감 임박" 파티 - 출발일이 "실행한 날 + N일" 이라 발표 전날이나 당일에 한 번 더 실행
mysql -u scit -p --default-character-set=utf8mb4 < src/main/resources/db/demo_urgent_parties_seed.sql

# 게시물·액티비티·투어 썸네일을 실제 관광지 사진으로 (사진 복사 + SQL 한 번에, 비밀번호를 물어봄)
DB_USER=scit bash src/main/resources/db/apply_demo_photos.sh
```

**예전부터 쓰던 DB 를 그대로 쓴다면** 아래 두 가지를 먼저 확인한다.

- **칭호가 4종(새내기 탐험가 등)만 보이면** v17/v18 칭호 마이그레이션이 빠진 것이다. `migration_v17_titles_catalog.sql` → `migration_v18_titles_distance_tiers.sql` 순서로 실행한다. 서버가 `titles.category` 컬럼을 이미 만들어 둔 DB 에서는 v17 첫 문장(`ALTER TABLE titles ADD COLUMN category ...`)이 "Duplicate column" 으로 실패하니 그 문장만 빼고 실행한다.
- **회원 아이디(username)가 비어 있으면**(Hibernate 가 컬럼을 먼저 만든 DB 는 기존 회원이 `''` 로 채워져 있다) `/yuja` 같은 프로필 주소가 안 열린다. `migration_v20_usernames.sql` 을 실행하면 이메일 앞부분으로 채워진다(직접 고른 아이디는 안 건드림, 재실행 안전). 확인: `SELECT COUNT(*) FROM users WHERE username IS NULL OR username = '';` 가 0
- **좌표 컬럼이 `DECIMAL(38,2)` 이면**(Hibernate 가 만든 테이블) 지도·날씨 좌표가 소수점 2자리로 잘린다. 아래를 실행한 뒤 `data.sql` 의 액티비티·투어 데이터를 다시 넣는다.
  ```sql
  ALTER TABLE activities MODIFY latitude DECIMAL(10,7), MODIFY longitude DECIMAL(10,7);
  ALTER TABLE tours      MODIFY latitude DECIMAL(10,7), MODIFY longitude DECIMAL(10,7);
  ```

### 2-2. `application-local.yml` (git 미추적 - PC 마다 따로 확인)

- AI 추천·타미 챗봇을 실제 Gemini 로 쓰려면 `app.companion` 아래가 이렇게 돼 있어야 한다.
  ```yaml
  companion:
    provider: gemini
    api-key: <결제한 프로젝트의 키>
    model: gemini-3.5-flash-lite
  ```
- 모델 이름 오타가 있으면 Google 이 404 를 돌려주고, 키의 선불 크레딧이 0 이면 402 를 돌려준다. 어느 쪽이든 화면에는 오류 없이 **키워드 매칭 폴백**만 나와서 알아채기 어렵다. AI Studio(https://ai.studio/projects)에서 크레딧 잔액을 확인해 둔다.

## 3. 여러 명이 동시에 접속하기 (채팅 시연)

채팅은 서버 안의 WebSocket(`/ws`)으로 오가므로, **모두 같은 서버(발표 노트북)에 접속**하면 된다.

1. 발표 노트북에서 서버 실행 (`./gradlew bootRun`).
2. 다른 사람은 **같은 Wi-Fi** 에 연결한 뒤 `http://<노트북 IP>:8080` 으로 접속한다. IP 는 현장에서 `ipconfig` 로 확인(장소마다 바뀐다).
3. 학교·행사장 Wi-Fi 는 기기끼리 통신을 막아 둔 경우가 많다. 접속이 안 되면 **한 사람의 휴대폰 핫스팟에 노트북과 모두가 연결**한다. 리허설 때 핫스팟으로도 미리 시험해 둔다.
4. Windows 방화벽에 Java 인바운드 허용 규칙이 있어야 한다(처음 실행할 때 뜨는 허용 창에서 허용).
5. 발표 중에는 노트북 **절전 모드를 끈다** - 잠들면 서버가 끊긴다.

주의할 점

- **사람마다 다른 계정**으로 로그인한다. 같은 브라우저의 탭끼리는 로그인 세션을 공유하므로, 노트북 한 대로 두 명을 보여줄 때는 일반 창 + 시크릿 창, 또는 크롬 + 엣지처럼 나눈다.
- 파티 채팅은 **같은 파티 멤버끼리만** 된다. 시연할 계정들을 미리 같은 파티에 넣어 둔다.

## 4. 시연 직전 체크리스트

- [ ] 메인 시연 흐름(번개모임 → 채팅 → 계획표)을 처음부터 끝까지 한 번 직접 눌러 보기
- [ ] **시연에 쓸 계정마다 로그인해서 `/mypage` 를 한 번 열기** - 칭호는 본인이 마이페이지를 열 때 지급된다. 안 열면 파티방·공개 프로필에 대표 칭호 배지가 안 붙는다
- [ ] 계정마다 칭호 관리(`/mypage/titles`)에서 눈에 띄는 칭호를 대표로 장착
- [ ] AI 추천 한 번 실행해서 폴백이 아닌 실제 응답이 오는지 확인 (2-2 참고)
- [ ] 게시판 첫 페이지에 테스트용 글(예: "화난문어", "하하")이 남아 있으면 숨기거나 삭제
- [ ] `demo_urgent_parties_seed.sql` 을 당일 기준으로 다시 실행했는지 (메인 "모집 마감 임박" 이 비어 보이지 않게)
- [ ] 서버를 재시작할 때 `8080` 포트가 이미 쓰이고 있다고 나오면, 남아 있는 `java` 프로세스를 작업 관리자에서 종료
